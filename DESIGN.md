# Design System: badil

## Overview

**Creative North Star: "The Category Standard"**

badil's site is a product page at the craft of the infrastructure tools its readers already trust: white ground, ink type, hairline borders, and the product itself shown at real scale. The page is the quiet frame; the illustrations (the live preview loop and the pull request still) are where the product's colour and detail live. Nothing on the page dresses up as a terminal or a dashboard: there is no mono costume, no grid background, no numbered panels.

Density is generous. Sections breathe on a large vertical rhythm, one idea per section, with a heading and its lead on the left and the evidence on the right. Depth is almost absent: everything is flat and separated by 1px hairlines, with one soft shadow reserved for the product panel in the hero.

Light and dark are equal citizens. Light is neutral gray on white; dark is green-tinted near-black, so the terminal green reads as native to the ground. A three-way theme control (System, Light, Dark) switches the page and every illustration together.

The docs at `/docs` carry the same world into a reading frame. Pages are sorted by what they are for, under three tabs (Guide, Concepts, Reference), each with a short sidebar; the column holds a 560px measure beside an "On this page" rail. Code is where the docs spend their colour: framed panels with a file bar, a pill Copy button and three quiet syntax hues. The docs home is the architecture map, the flow from GitHub to the preview namespace drawn as hairline nodes on a canvas stage. The docs share the landing's theme choice (`badil-theme`), so switching on one switches both.

**Key Characteristics:**
- White ground (dark: green-tinted near-black), ink text, 1px hairlines.
- One green, meaning live/healthy/ready; one amber, meaning a pinned commit.
- One face, Schibsted Grotesk, for all text; the system mono for code only.
- Pill buttons and chips, 10px panels, a 16px stage frame.
- Flat everywhere except the hero's product panel.
- Docs: tabs by content type, a 560px reading measure, framed code with three syntax hues kept inside the frame.

## Colors

A neutral, near-monochrome palette whose only hues are status signals borrowed from the product, plus three syntax hues that live only inside docs code frames.

### Primary
- **Status Green** (light `status-green`, dark `terminal-green`): means live, healthy, ready, or "this preview exists". Used for ready dots, "Synced · Healthy" text, the `preview` label chip, links inside the PR comment, the dashed twin of the mark, and the text caret. Never a button fill, never a section background.

### Secondary
- **Pin Amber** (light `pin-amber` on `pin-amber-soft`, dark `night-pin-amber` on a 14% tint): marks a pinned commit SHA, and only that.

### Tertiary
- **Syntax hues** (light `code-string`, `code-command`, `code-constant`; dark `night-code-string`, `night-code-command`, `night-code-constant`): rose for quoted strings, blue for commands and functions, violet for constants, variables and flags. They colour code in the docs' code frames (`docs/lib/code-themes.ts`) and nowhere else. Code keys and keywords are ink, plain text slate, comments and punctuation faint (comments italic). On the dark code ground the plain text and the faint tokens are lifted to `night-code-text` and `night-code-faint`. Every syntax colour clears 6.6:1 on paper and 5.3:1 on night canvas.

### Neutral
- **Paper** (`paper`) / **Night** (`night`): the page ground.
- **Canvas Gray** (`canvas-gray`) / **Night Canvas** (`night-canvas`): tinted sections (the pull request section) and the file card's path bar; also the dark panel surface.
- **Hairline** (`hairline`) / **Night Hairline**: every border and divider. **Hairline Strong** (`hairline-strong`): scrollbar thumb and the loop's routes.
- **Ink** (`ink`) / **Night Ink** (`night-ink`): headings, strong text, the primary button fill (inverted in dark: the button is light on near-black).
- **Slate Text** (`slate-text`) / **Night Text** (`night-text`): body copy.
- **Faint Slate** (`faint-slate`) / **Night Faint** (`night-faint`): step numerals, inactive theme icons, metadata and SHAs in mockups.
- **Code Well** (`code-well`) / **Night Code Well**: inline code background, the pressed theme button and the docs home's install icon disc.
- **Link Underline** (`link-underline` / `night-link-underline`): the 1px underline under docs links, green at 40%; it turns solid green on hover.
- **Selection** (`selection-green` / `night-selection-green`): text selection in the docs.
- **Overlay** (`overlay` / `night-overlay`): the scrim behind the docs search dialog.
- **Diff tints** (`diff-add`, `diff-remove`): Fumadocs' tokens for added and removed lines in code, a 10% green and a 6% ink wash, with green and faint symbols.

Docs callouts stay in the palette: info and idea are faint slate, warnings and errors are ink, success is status green. Mermaid diagrams are drawn from the same tokens (white or night-canvas nodes, hairline-strong borders, slate or night-text lines).

The illustrations (`src/stage/tokens.css`, `src/stage/pr-still.css`) carry their own `--ss-*` set whose values equal the page's in both themes: accent, amber, hairline, dark ground and neutrals. A stage uses its `--ss-*` tokens, and they match the page tokens.

### Named Rules
**The Product Owns the Green Rule.** Green is a status, not a brand fill. It appears where the product would show it (ready, healthy, labelled, linked) and on the mark's dashed twin (the preview, the double of production); it never fills a button, a section or a heading.

**The Amber Means Pinned Rule.** Amber marks a pinned commit and nothing else. No warnings, no highlights.

**The Syntax Stays In The Frame Rule.** The three syntax hues colour code inside a code frame and nothing else. Status green and pin amber never colour code; inline code is ink on the code well.

## Typography

**Display Font:** Schibsted Grotesk Variable (with system-ui, -apple-system, Segoe UI, sans-serif)
**Body Font:** Schibsted Grotesk Variable
**Label/Mono Font:** system mono stack (ui-monospace, SF Mono, Menlo, Consolas), for code only

**Character:** One grotesk carries everything, tightened and heavy (650) at heading sizes, open and plain at body size. Mono appears only where the content is literally code: SHAs, paths, labels, YAML.

### Hierarchy
- **Display** (650, clamp(36px, 3.9vw, 54px), 1.04, -0.032em): the hero headline only; max 30ch, balanced wrap.
- **Headline** (650, clamp(26px, 2.6vw, 36px), 1.12, -0.024em): one per section.
- **Title** (600, 18px, 1.35, -0.01em): step titles, evidence terms, the comparison heading.
- **Lede** (400, 20px; 18px on phones, 1.55): the hero sentence, max 36em.
- **Body** (400, 17px, 1.6): all copy; measures held between 26em and 62ch.
- **Label** (500, 15px): nav and footer links. Buttons use 600, 16px, -0.005em.
- **Mono** (0.84em inline; 12px in panels): code, paths, SHAs. Inline identifiers never wrap; in the docs, only inline code that is a command or a message (a space and over 24 characters, or over 48 characters) may wrap, at its spaces.

The `wordmark` (19px), `wordmark-small` (16px) and `button` (16px) roles size the wordmark and buttons; `ui` (13px), `ui-small` (12px mono) and `chip` (12px) size the product fragments: the file panel, the evidence panels and the chips.

### Docs hierarchy
- **Docs Title** (`docs-title`, 650, clamp(32px, 3.2vw, 40px), 1.08, -0.03em): the page H1, balanced wrap.
- **Docs Heading** (`docs-heading`, 650, 24px, 1.25, -0.02em) and **Docs Subheading** (`docs-subheading`, 600, 19px, 1.35, -0.01em): H2 and H3 in the body.
- **Docs Lead** (`docs-lead`, 400, 19px, 1.55; 17px on phones): the first paragraph of a page.
- **Docs Body** (`docs-body`, 400, 17px, 1.65; 16px on phones): all page text; strong is 600.
- **Docs Card Title** (`docs-card-title`, 600, 17px, 1.3): the install card and the map's node names.
- **Docs Table** (`docs-table`, 400, 15px, 1.5): table cells and the install card's description; table headers are 600 14px. Header links, tabs and the "Docs" label use **Label** (500, 15px).
- **Docs Sidebar** (`docs-sidebar`, 14.5px, 1.35): sidebar page links and Install's steps.
- **Docs Small** (`docs-small`, 14px, 1.5): the search pill, map node text, map links (500) and the map notes.
- **Docs TOC** (`docs-toc`, 13.5px, 1.4): the "On this page" rail (its title 600) and the map's in-node return line.
- **Docs Meta** (`docs-meta`, 500, 13px): the Copy pill, the map's edge and side labels; the step numerals and the "optional" tag are 13px at 400, numerals tabular.
- **Docs Lane** (`docs-lane`, 500, 12.5px): the map's lane labels and, in the wide row, its edge labels.
- **Docs Kbd** (`docs-kbd`, 500, 12px, 20px line): the search shortcut and the code bar's language label.
- **Code Block** (`code-block`, mono 13px, 1.7) under a **Code Title** (`code-title`, mono 12.5px) in the code frame's bar.

### Named Rules
**The Mono Is Code Rule.** Mono is set only on text that is literally code or a git identifier. Headings, labels and UI chrome are always in the grotesk.

## Layout

A centred column of 1184px max with a 32px gutter (20px under 600px). Sections stack on a fluid rhythm (clamp(80px, 10vw, 136px) top and bottom), separated by hairlines or a full-bleed canvas tint.

The working pattern is the split: heading and lead on the left (4fr) and content on the right (7fr), 56-72px apart; when the lead carries the file card it takes 7fr and the steps 5fr, so the file reads without scrolling; it collapses to one column at 960px. The evidence row is three equal columns (40px row, 32px column gaps), one column at 960px. The pull request section pairs copy, top-aligned, with the still at its 680px design width, stacking at 1119px. The close is the one centred block. Spacing steps are multiples of 4px; 2px is the hairline step of the theme control, the gap between wrapped illustration rows and the vertical padding of inline code.

The hero is left-aligned copy above the live loop. At 1148px and wider the loop sits in the framed hero panel; below that the frame drops and the loop's tablet and phone designs sit on the page ground, edge to edge (16px gutter on phones so the 358px phone design shows at 1:1).

Breakpoints: 1147px (hero frame off), 1119px (PR stacks), 960px (splits and evidence stack), 599px (phone gutter, nav shows the mark alone).

### Docs
The docs use Fumadocs' notebook layout. A 64px header (`docs-header`) carries the wordmark and "Docs", the search pill, the badil.dev and GitHub links and the theme control; from 64rem a 47px tab bar (`docs-tabs`) sits under it, tabs 28px apart. Below 64rem the tabs move into the sidebar's dropdown and the phone drawer, and the badil.dev and GitHub links into the drawer. The sidebar lists the tab's pages as 34px rows (`docs-sidebar-item`), with Install's numbered steps under it when it is the page being read; the "On this page" rail sits on the right, 44px from the top.

The column is padded 44px at the top and 64px at the sides from 80rem (`docs-page-top`, `docs-page-inline`). Paragraphs, lists, headings and quotes hold a 35rem measure (`docs-measure`, about 70 characters at 17px); tables, code frames and diagrams take the full column and scroll sideways inside their own frame, never the page. A Mermaid diagram keeps a minimum width of 75% of its natural size, so its labels stay at 12px or more.

The docs home map is a row of five equal nodes with 64px edge columns (`map-edge`) when its container is 900px or wider, and a single column below that.

Docs breakpoints: 80rem (column padding), 64rem (tab bar), 48rem (header side padding 32px; the search pill is hidden below), 40rem (phone type sizes, the install card's pill goes full width), and the map's 900px container query.

## Elevation & Depth

Flat by default: depth is made with hairlines and the canvas tint, not shadows. One shadow exists on the page, the hero panel's soft offset (`--panel-shadow`); in dark it becomes a faint inset top highlight over a deep drop. Inside the illustrations, surfaces are separated by 1px hairline rings drawn as box-shadows, never soft shadows.

### Shadow Vocabulary
- **Product panel** (`0 1px 2px rgba(16,20,24,0.04), 0 24px 48px -28px rgba(16,20,24,0.22)`): the hero's product panel only, at 1148px and up.
- **Hairline ring** (`0 0 0 1px` the stage line color): illustration windows and cards.

The docs add no shadow. Their header is paper at 92% with the same saturate(1.4) blur(10px) backdrop as the landing's nav.

### Named Rules
**The One Shadow Rule.** The hero's product panel carries the page's only shadow. Every other surface is flat, bordered by a hairline.

## Shapes

Rounded but disciplined, four radii. Pill (999px) for anything you press or that labels state: buttons, the theme control, chips, ready badges. Panel (10px) for content cards: the file card, the evidence mockups, the PR comment card. Stage (16px) for the frames around an illustration: the hero panel and the PR still's crop. Code (5px) for inline code and pinned SHAs. Borders are always 1px hairlines; dots are circles. The PR still runs off the bottom under an 80px fade rather than being cut mid-line.

`focus` (4px) is the focus ring's radius.

The docs use the same four radii: pill for the search, Copy, sidebar rows, the theme control and the docs pill; panel for code frames, tables, callouts, the footer cards, the install card and the map nodes; stage for the map's canvas stage and its dashed "Your side" box; code for inline code and the bottom corners of the map's return lanes. `marker` (2px) rounds the active tab's 2px ink underline. Dashed borders exist only on the map ("Your side" and the return lanes), at 1px. The map notes' bullets are 4px circles. Icons are drawn on a 16-unit grid with 1.4 to 1.6 strokes (the GitHub mark is filled) and shown at 13 to 16px.

## Components

### Buttons
Plain and confident: one ink pill, one quiet text link.

## Do's and Don'ts

### Do:
- **Do** keep the page on paper/night with hairline (`#e3e5e8` / `#232823`) borders and let the illustrations carry the colour.
- **Do** use green only for live, healthy, ready, labelled or linked states, and amber only for pinned commits.
- **Do** use the ink pill for the single primary action and a quiet text link beside it.
- **Do** set every text in Schibsted Grotesk and reserve mono for code, paths and SHAs.
- **Do** switch the page and every illustration together when the theme changes.
- **Do** frame every docs code block with its bar and Copy pill, and keep the syntax hues inside that frame.
- **Do** hold docs body text to the 35rem measure; let tables, code and diagrams scroll inside their frames rather than the page.
- **Do** keep the docs' active page and links in status green, and every other docs chrome in ink, slate and faint.

### Don't:
- **Don't** add a second shadow; the hero product panel owns the only one.
- **Don't** fill buttons, sections or headings with green.
- **Don't** put eyebrows or kickers above headings, grid backgrounds, numbered decorative panels, or mono-set UI chrome.
- **Don't** frame the loop below 1148px; the smaller designs sit on the page ground.
- **Don't** colour code with status green or pin amber, or use a syntax hue outside a code frame.
- **Don't** let an identifier in inline code wrap.
